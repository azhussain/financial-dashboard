Stocks Explorer

A live global market dashboard: the top 20 stocks across the Americas, APAC, and EMEA, refreshed automatically on a market-hours-aware schedule and pushed to dashboards the moment values change — plus interactive candlestick charts and an AI-powered Virtual Agent for stock insights.

Java 17 · Spring Boot 3.5 React 19 · TypeScript · Vite · Tailwind Yahoo Finance data SSE push updates LangChain4j + OpenAI Docker · AWS (S3 + CloudFront + EC2)

1 · What it does

For business: Stocks Explorer is a watchlist-first market monitor. Three regional columns show each market's twenty largest companies with live prices in local currency. Clicking a stock opens a details panel with a candlestick chart and key metrics. A floating Virtual Agent answers questions — comparisons, "where do I invest $X", price explanations — using the same live data the dashboard shows.

Live regional watchlists

Top 20 per region by USD-normalized market cap. Currency chips, market status, last-updated time, STALE markers, and per-region refresh buttons.

Push, not poll

A backend Markets Agent refreshes on a shared schedule and pushes only what changed over server-sent events. Unchanged rows never re-render.

AI Virtual Agent

Floating chat (bottom-right) grounded in live quotes and history; per-tab conversation memory; charts only on request; local-currency pricing.

4 · The live-data pipeline (Markets Agent)

Every cycle, each regional worker runs the same five-stage pipeline. One shared schedule serves all viewers — nobody's browser triggers its own Yahoo calls.

1 · Fetchfull candidate pool (~25/region), one batched call
→
2 · RankUSD-normalized market cap, same-company dedupe, top 20
→
3 · Diffdisplayed fields vs cached snapshot
→
4 · StoreRegionSnapshot: quotes + freshness + marketOpen
→
5 · PublishSSE market-update: changed rows + rank order only

Why this shape

  • Full-pool refresh — re-ranking the entire candidate list each cycle lets a new company displace the incumbent top 20; refreshing only the current 20 could never detect that.
  • Diff-then-publish — unchanged prices produce an event with an empty changed[]; React merges by symbol with identity-preserved objects + memoized rows, so unchanged UI does zero work.
  • Failure-proof — a failed refresh calls applyFailure, which retains last-good quotes and marks the snapshot stale. Bad or partial responses can never overwrite valid data. Backoff is bounded (30s → 5 min cap).
  • Reconnect-safe — new SSE subscribers immediately get a snapshot event with the entire cache; a 25s heartbeat keeps proxies from idling the stream.
SSE event shapes — snapshot: {REGION: RegionSnapshot} · market-update: {region, lastSuccessAt, lastAttemptAt, stale, consecutiveFailures, changed[], order[], marketOpen}.

5 · Adaptive cadence

Polling a closed market every five minutes wastes calls and yields nothing. Each worker declares the trading sessions of the exchanges it covers; a region is "open" while any window is in session. Cadence follows the market:

RegionCovered sessions (local)Open cadenceClosed cadence
AMERICASNYSE/Nasdaq/TSX — 9:30–16:00 ET, Mon–Fri5 min30 min
APACTokyo 9:00–15:00 · Hong Kong 9:30–16:00 · Seoul 9:00–15:30 · Taipei 9:00–13:30 · Sydney 10:00–16:00, Mon–Fri5 min30 min
EMEAContinental Europe 9:00–17:30, Mon–Fri · Tadawul 10:00–15:00, Sun–Thu5 min30 min

Closed ≠ ignored: a reduced 30-minute cadence still tracks pre/post-market moves and lets a region discover "open" on its next pass. The UI reflects state with a closed chip and a disabled refresh button; manual refresh otherwise bypasses the cadence entirely.

Exchange holidays aren't modeled — on a holiday the agent polls at open cadence and simply finds unchanged values. Adding a holiday calendar per exchange is a documented enhancement.

7 · Agents

The Virtual Agent

A genuinely agentic component: LangChain4j AiServices + OpenAI tool calling. The model plans its own tool usage, grounds every number in a fresh fetch, and answers in markdown bullets.

Tools

searchStocks · getTopStocks · getRegionalTopStocks · getStockHistory — all over the same StockService the dashboard uses.

Memory

Per-sessionId 20-message window; the browser sends a UUID kept in sessionStorage, so each tab is an isolated conversation.

Charts on demand

Tool-collected candle series attach to the reply only when the message asks for a chart/graph/plot/candlestick — a 300-word answer stays text.

  • Local-currency pricing (SAR, KRW, €, ¥…) with approximate USD conversion against stated budgets.
  • Investment-style answers include a "not financial advice" disclaimer by prompt contract.
  • ThreadLocal chart collector keeps the LLM context small while the UI gets full candle series.

The agent mesh (Stage 1)

Beneath the Virtual Agent sits a task-routed mesh — the gateway → orchestrator → workers → evaluator spine of a full agentic architecture, kept deliberately single-JVM (separate containers per role would waste ~1.5 GB on a t3.small; the contracts are what Stage 2/3 swap for SQS + per-role services).

GatewayBearer / X-API-Key auth on /api/agent/**
→
Orchestratoraccepts tasks, routes by type
→
TaskQueuein-memory now; SQS-shaped interface
→
WorkersDataAgentWorker: quote · snapshot · refresh
→
Evaluatorrule checks; reject → retry once
→
Auditin-memory ring or durable Redis list
  • Extensible roles — a new agent is a bean declaring its taskTypes(); routing needs no wiring changes.
  • Evaluator gating — results are sanity-checked (positive price + currency, non-empty non-stale snapshot) before being served; rejected output is retried once, then marked FAIL.
  • Auditable — every terminal outcome records {taskId, type, status, attempts, durationMs, reason, timestamp}; deploy/docker-compose.yml runs app + Redis so the trail survives restarts.
  • Chat is protected too — the gateway covers /api/agent/chat, closing the open-quota risk when AGENT_API_KEY is enabled.

8 · Security & resilience

  • Secrets — OPENAI_API_KEY is env-only (${OPENAI_API_KEY:} in properties); nothing secret is in the repo. No key → agent returns 503, everything else works.
  • CORS — CORS_ALLOWED_ORIGINS env allowlist; dev default localhost:5173.
  • Error hygiene — internal exceptions logged, never echoed; generic {"error"} bodies; verified by ApiSecurityTest (injection payloads, unknown endpoints, leak checks).
  • Quota protection — GatewayAuthFilter keys /api/agent/** when AGENT_API_KEY is set; add an AWS WAF rate-based rule on /api/agent/* at the distribution for defense in depth.
  • Staleness over wrongness — outages surface as STALE badges + retained data, never silently swapped values.
  • Yahoo quirks handled — browser User-Agent required (429 otherwise); cookie+crumb for quote endpoints with auto-refresh on 401/403.

9 · Deployment

All-in on AWS behind one CloudFront distribution: the default behavior serves the React SPA from a private S3 bucket (origin access control — the bucket is never public), and /api/* proxies to the Spring Boot container on EC2 (Docker, image in ECR, secrets in SSM Parameter Store). Same-origin means no CORS config and no VITE_API_BASE at build time.

Frontend → S3 + CloudFront

npm run build → aws s3 sync dist/ → invalidation. SPA fallback via CloudFront error responses (403/404 → index.html). HTTPS free on the cloudfront.net domain.

Backend → EC2 + ECR

Multi-stage Dockerfile on a t3.small (--restart unless-stopped). SG allows 8080 only from CloudFront's origin-facing prefix list. Env: OPENAI_API_KEY (from SSM SecureString), PORT. Probe: /api/health.

CI/CD → GitHub Actions

Push → test → ECR push → SSM rolling restart; S3 sync + invalidation. OIDC auth, no stored keys. Full runbook: deploy/aws-setup.md. ~$15–20/mo all-in.

SSE streams through CloudFront — /api/* disables caching and compression, and the app's 25s heartbeat stays under the 60s origin read timeout.
